# Task: MOXBOTS-MOBILE-002 representative native mobile UI

## Objective

Create a pinned Expo 58 / React Native 0.88 TypeScript internal mobile app using Expo Router and a typed adapter to the parent-owned `MoxBotsRemote` native module. Implement a reviewable login, approved target/session list, and representative conversation flow with the accepted compact V6 layout. Keep QA fixtures explicit and web-only; production UI must use native replies and show unavailable states honestly.

## Acceptance criteria

- [x] Isolated app package and lockfile use SDK-compatible pinned Expo/React Native versions and a custom development client.
- [x] Typed bridge wrapper validates closed intents and structured replies; no JavaScript credential or mutation persistence.
- [x] Representative conversation layout: single compact header with back/title/Bot/results/more; spacious two-sided transcript with timestamps; one-line resting composer with plus, microphone when empty, send arrow for draft.
- [x] Login/session selection and new/continue conversation use native adapter; explicit disconnected, unavailable, unknown mutation and unavailable voice/attachment states.
- [x] QA fixture only activates for development web with `EXPO_PUBLIC_MOBILE_QA=1` and carries a visible synthetic-data banner.
- [x] Representative QA scenarios cover multiple/offline Bots, approval/deny and stale approval, unknown receipts (including restart-restored pending), and network errors.
- [x] Voice UI uses closed native start/stop/cancel intents, receives typed change events, keeps partial/final text in the editable draft, and never auto-sends; async speech errors are localized and retain their error code behind details.
- [x] Drafts use native stable target identity plus session scope, revision-checked native read/write intents, debounced single-flight saves, conflict preservation, and account-scope clearing; all-offline composer explains that text remains a draft.
- [x] Mobile protocol capabilities/models/suggestions and native attachments are wired through closed typed intents; sends include only ready asset IDs, pending receipts preserve their session/mobile protocol, and only explicit capability-unsupported replies enable text-only legacy fallback.
- [x] Attachment controls are scoped to the selected account/target/session, serialized through terminal upload states, and expose native pause/resume/status/cancel semantics; uncertain sends remain query-only and do not replay or mint replacement operation IDs.
- [x] Explicit web QA fixtures expose supported/unsupported/error protocol states and restore both session and mobile pending-operation kinds; fixture behavior remains banner-labeled synthetic data.
- [x] Parent and independent UI acceptance review completed for representative conversation layout and QA state flows.
- [ ] Native build and bridge integration validation on configured Android SDK/device; iOS build requires full Xcode.

## Completed

- Scaffolded `mobile/app` and moved Expo Router routes under `src/app/` as required by local AGENTS.
- Added account status/login polling/logout, target/session list, session snapshot polling, send/start, pending receipt query, stale approval refresh guard, and compact chat UI.
- Added Lucide native icons and SDK-compatible `react-native-svg`; adjusted catalog runtime to nullable because authoritative approved target metadata omits runtime.
- Added deterministic policy tests for query-only uncertain mutations and stale approvals.
- QA web flow verified in shared IAB: realistic transcript and timestamps; results and device panels; composer, draft retention, and send; multiple/offline Bot states; network error disclosure; approval/deny and stale refresh; unknown and restart-restored pending receipts without replay. Voice remains explicitly unavailable in web fixture mode.
- Native speech contract consumes `speech.start`, `speech.stop`, and `speech.cancel` replies plus `speechChanged` events; this is typed integration only until the parent-owned Expo module is integrated and built on device.
- Added persistent draft controller with per-identity/session keys, owner/edit revision fencing, debounce and serial writes, stale revision conflict refresh, and draft-error visibility. Browser fixture uses localStorage only under the explicit web QA flag and labels this as simulated browser storage; it is not proof of native KeyStore persistence.
- Added deferred tests for late read vs typing, stale owner save, reload and rename identity, conflict preservation, typing during a slow save, write failure retention, and account/session key isolation. Added offline composer explanation and button roles/selected state for target chips and session rows.

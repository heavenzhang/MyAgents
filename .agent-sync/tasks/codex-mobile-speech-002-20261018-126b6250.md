# Task: Mobile native on-device speech capture and editable draft

## Objective

Provide native iOS and Android speech capture that returns partial and final transcripts as an editable draft. Scope is limited to two platform implementation files; the parent module owns JS intent routing, event delivery, permission wiring and UI. Recognition must remain on-device and user initiated.

## Acceptance criteria

- [x] iOS uses AVAudioEngine/SFSpeechRecognizer and sets `requiresOnDeviceRecognition`; unavailable local recognition fails closed.
- [x] Android uses `createOnDeviceSpeechRecognizer` only and checks API/service availability before capture.
- [x] Both expose recording/transcribing/idle snapshots and partial/final transcript events; cancellation and stale callbacks are fenced.
- [x] Permission, availability, start, no-match, stop and timeout failures use stable `MOBILE_SPEECH_*` codes.
- [ ] Parent integrates module routing, app permission strings and Android runtime permission request.
- [ ] Native builds and real-device recording/transcript/editable-draft flow are verified; no device result is claimed by this implementation task.

## Completed

- Added `mobile/app/modules/moxbots-remote/ios/NativeSpeech.swift` and Android `NativeSpeech.kt`.
- iOS sequentially requests Speech and microphone permissions after start invocation; it accepts only `zh-CN`, `en-US` and `ja-JP`, requires on-device support, reports partial results, and bounds stop/transcription wait to 12 seconds.
- Android requires parent-mediated `RECORD_AUDIO`, API 31+ on-device service availability, and creates only the OS on-device recognizer; capture is capped at 60 seconds and stop wait at 12 seconds.
- Both platforms serialize recognizer access on the main thread, fence late callbacks by generation and expose current transcript snapshots. Neither sends or uploads audio to an external provider.

## Blockers and unknowns

- This worktree lacks a full mobile app build tree and local Kotlin compiler; integrated Android and iOS native compilation remain unverified.
- Parent must add `NSSpeechRecognitionUsageDescription` and `NSMicrophoneUsageDescription` to app configuration. Android parent must request `NativeSpeech.RECORD_AUDIO_PERMISSION` from the current Activity before calling `start` and add the Android 11+ `<queries>` declaration for `android.speech.RecognitionService`.
- Platform language model availability varies by device; unavailable locales/services return closed error codes. No real-device, permission-prompt, acoustic or transcript quality claim is made.

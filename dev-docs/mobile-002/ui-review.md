## 缺陷与未覆盖项

1. **中：空 composer 高于视觉基线。** 聊天页空态在 480 px 内容宽度和 390 px 视口下，胶囊高度约 63 px；目标约 44 px。复现：打开任一会话，清空输入框，观察底部 composer。证据：`chat-390.png`、`chat-360.png`。已同步实现者，请修复后复测。
2. **中：后端错误可能向用户显示原始码或英文状态。** 源码中通用错误处理将 `error.message` 直接送入提示，突变分支将 `result.code` 作为可见文本，状态查询直接渲染 `操作状态：${result.status}`；例如 `MOBILE_RECEIPT_REQUIRED` 会裸露给用户，`accepted`/`rejected` 以英文显示。期望是简短中文动作与状态，原始码收进可展开的技术详情。来源：`src/app/index.tsx` 的 `run`、`mutation`、`queryPending`、`respond` 错误路径。已同步实现者；fixture 不返回这些失败码，未能在 UI 中实测。
3. **未覆盖：多 Bot / Agent 筛选。** fixture 只提供一个在线 Bot；点选唯一 Bot 芯片没有可观察的筛选变化。多目标选择和筛选结果不可验证。
4. **未覆盖：未知回执、重复发送保护和审批刷新/拒绝/变更保护。** fixture 的发送总返回 `accepted`，待查询列表始终为空，审批列表始终为空；这些状态不能通过当前 UI fixture 构造。源码路径仅供定位，不能替代行为验收。
5. **未覆盖：离线恢复与原生附件/语音。** fixture 的目标始终在线，且对应能力明确不可用。

首次打开标签时 Expo 页面短暂显示 `Cannot access 'loadSessions' before initialization`（旧 bundle 错误记录时间为 2026-10-17）。对当前运行页执行硬 reload 后稳定进入会话列表，并完成上述交互；后续操作未再现。该首次错误不计作当前 reload 后通过的运行态故障，但应由主任务核对最终打包版本。

**结论：** 代表性浏览器聊天页的核心可见布局和合成发送路径通过；视觉基线仍有 composer 高度偏差，错误文案与真实原生/审批/未知回执路径仍未验收。不得据此宣布原生或真实后端 UI 验收完成。
